# PvZModManager 超大型 Mod 管理器方案

> 状态：设计稿，尚未实现。目标是在三级扩展运行时落地前建立统一的桌面管理工具。本工具与 `PvZAnimationStudio`、`PvZLuaStudio` 是三个独立产品，不把脚本编辑、动画制作、插件和全局配置管理塞进同一个应用。

## 1. 产品决定

项目后续固定拆成四个职责清晰的部分：

1. **`PvZAnimationStudio`：动画资产制作器**。只负责 Reanimation、图片部件、动作、定位轨道、预览和基础植物创建所必需的最小元数据。
2. **`PvZLuaStudio`：Lua 行为编辑器**。专门负责 Lua 创建、编辑、绑定辅助、语法/API 校验、Mock 调试、错误跳转和运行时脚本诊断。
3. **`PvZModManager`：Mod 总管理器**。管理所有 `pvzmod` 配置、包、Lua 资产、DLL、图片、动画、音效、自定义内容、依赖、冲突、安装档案和启用状态，但不编辑、验证或打开 Lua 代码。
4. **`pvzmod.dll`：运行时宿主**。只加载管理器部署的运行目录，并对实际加载内容执行自己的强制安全校验；它负责 Hook、事件、Capability、Lua 和原生插件，不承担编辑器职责。

最重要的边界是：

- “创建 Lua、写入绑定、验证并打开待编辑位置”属于 `PvZLuaStudio`，既不属于动画制作器，也不属于管理器；
- 动画制作器不浏览或启停 DLL，不管理包依赖，不合并全局配置，不提供事件/Capability 总控台；
- 管理器把 Lua 当作带所有者、版本、哈希、路径和启用状态的受管资产，只显示外部校验报告摘要，不解析 Lua 语义、不承载代码编辑器、不跳到代码行；
- 三个桌面工具通过公开文件契约协作，不互相嵌入全部业务代码；
- 运行时不把管理器工程数据库当配置来源，只读取普通、可审查、可手工编辑的 JSONC/Lua/manifest 和生成索引。

## 2. 三个桌面工具的边界

| 能力 | PvZAnimationStudio | PvZLuaStudio | PvZModManager |
| --- | --- | --- | --- |
| Raw/compiled Reanimation 读取、编辑和导出 | 负责 | 不负责 | 只管理资产记录、引用、安装位置和预算 |
| 分层画布、时间轴、曲线、动作和定位轨道 | 负责 | 不负责 | 不重复实现 |
| PNG/JPG 部件导入、子帧和动画内图片绑定 | 负责 | 不负责 | 管理最终资源 ID、路径、引用和预算 |
| 基础植物骨架 | 可填写预览/导出所需的名称、载体模板、卡片基础值和动画引用 | 只读取绑定目标摘要 | 决定最终 ContentId、包归属、完整配置和安装结果 |
| Lua 创建、编辑、绑定辅助、Mock、热重载诊断 | 不负责 | 负责 | 只管理文件、模块、所有者、版本、哈希和启用状态 |
| Lua 语法/API/能力验证和错误跳转 | 不负责 | 负责 | 不负责；只显示外部报告是否存在及其摘要 |
| DLL manifest、PE32/ABI/hash、依赖和信任 | 不负责 | 不负责 | 负责静态管理；不把第三方 DLL 加载进管理器进程 |
| JSON/JSONC 全局配置和分包覆盖 | 不负责 | 只读取必要的绑定上下文 | 负责 |
| 植物/僵尸/子弹/精英/Boss/UI 内容目录 | 只提供动画预览模板 | 只读取可绑定目标 | 负责统一 ContentCatalog |
| 包安装、启用、禁用、升级、回滚 | 不负责 | 不负责 | 负责 |
| 冲突解决、依赖图、版本锁定 | 不负责 | 只报告 Lua 模块内问题 | 负责包和安装层问题 |
| 游戏版本、包状态和安全点重载请求 | 不负责 | 负责脚本开发连接 | 负责运行档案管理 |
| 发布输出 | 动画资产包 | Lua 模块、绑定描述和校验报告 | 最终 Mod 发布包与安装档案 |

这里的“基础植物骨架”不是让动画制作器继续拥有植物系统。它只保存完成动画预览和资产交接所需的字段，例如：

```text
draftId / displayName
carrierPlantId / carrierReanimation
animationId / actions / locators / texture bindings
可选的 cost / recharge / health 预览默认值
```

技能绑定、Lua 参数、包依赖、覆盖顺序、启用状态、存档 Schema 和最终安装路径都不写进动画制作器的职责。

## 3. 动画资产交换契约

`.pvza` 继续是动画作者的可编辑工程，不能直接充当已安装 Mod 包。动画制作器另外导出一个公开结构的普通目录或 ZIP，例如：

```text
<animation-id>.pvzanim.zip
├─ animation-asset.jsonc       # 公开 Schema、版本、动作、定位轨道、引用和哈希
├─ animation/
│  ├─ <id>.reanim              # 可选 Raw
│  └─ <id>.reanim.compiled     # 可选 compiled
├─ images/                     # 该动画使用的图片
└─ plant-bootstrap.jsonc       # 可选；只含基础植物骨架，不含技能或包状态
```

`PvZModManager` 导入时完成以下工作：

1. 校验 ZIP 路径、大小、文件数、图片尺寸、Reanimation 和 Schema；
2. 让用户选择目标包和命名空间；
3. 把草稿 ID 转为最终 `namespace:name` ContentId；
4. 预览将新增/复用/冲突的贴图、动画和植物定义；
5. 写入目标包源目录并建立引用；
6. 运行资源/配置/包结构预检，读取已有的动画或 Lua 工具报告摘要，用户确认差异后再安装到游戏档案。

交换包不能包含 DLL、可执行脚本、包启用状态或让管理器静默覆盖其他包的指令。这样打开一个动画项目不会意外执行代码或修改整个 Mod 环境。

## 4. 管理器掌管的范围

### 4.1 游戏与安装档案

管理器支持多个游戏目录和多个 Mod 档案：

- 核对 `PlantsVsZombies.exe` 位数、时间戳、哈希和受支持版本；
- 显示 `pvzmod.dll` 版本、脚本 API、插件 ABI 和是否需要重启；
- 每个档案拥有独立的启用包集合、配置覆盖、生成索引和回滚记录；
- 游戏运行时禁止替换 `pvzmod.dll` 和原生插件；JSON/Lua 只通过运行时安全点请求重载；
- 安装前生成明确计划，列出新增、修改、删除、保留和冲突文件。

### 4.2 包和依赖

每个扩展包有稳定 `packageId`、版本、作者、许可证、依赖、可选依赖、目标游戏版本、API/ABI 要求和内容清单。管理器负责：

- 创建、导入、复制、启用、禁用、升级、降级和卸载；
- 依赖拓扑、循环检测、版本范围、缺失能力和冲突解释；
- `ownerId + generation` 预览，以及禁用后会撤销的 JSON/Lua/DLL/资源/UI 项；
- 生成 `pvzmod/config/extensions/packages.jsonc` 和发布锁定文件；
- 禁止“最后加载者获胜”，字段覆盖和 Modifier 必须显式声明。

### 4.3 全部配置

管理器为以下配置提供 Schema 表单和原始 JSONC 双视图：

- 关卡、波次、出怪和地图规则；
- 植物、僵尸、子弹、防具、精英和 Boss；
- 贴图、动画、音效、粒子和定位轨道；
- UI 布局、卡片、菜单、图鉴和设置；
- 有限 JSON MicroRule；
- Lua 模块索引、插件 manifest、包索引和全局设置。

表单和源码不是两份数据。底层使用保留注释、顺序、未知字段和格式的 lossless JSONC 文档模型；任何表单编辑都生成可预览的最小文本差异。管理器不能为“格式化方便”重写整个文件，也不能删除未来版本字段。

### 4.4 Lua 资产管理，而不是 Lua 编辑器

管理器的 Lua 页面只做资产清单和安装管理：

- 显示模块 ID、包所有者、版本、相对路径、哈希、API 版本、声明能力和启用状态；
- 显示由 `PvZLuaStudio`/CI 生成的最近校验报告时间、工具版本、源码哈希和通过/失败摘要；
- 管理模块随哪个包安装、哪些实体绑定它、禁用后影响哪些内容；
- 检查文件是否缺失、路径是否逃逸、manifest 是否重复以及哈希是否与安装计划一致；
- 请求运行时启用、禁用或安全点重载某个已管理模块。

管理器明确不做：

- 不显示或编辑 Lua 源码；
- 不负责语法、API、类型、能力、死循环、指令预算或 Mock 验证；
- 不创建 Lua 文件，不写代码模板，不跳转文件和行号，也不承担“打开代码”；
- 不把外部校验报告当成运行时安全校验的替代品。

Lua 作者单独启动 `PvZLuaStudio` 打开相同的包源工作区。完整 Lua 工具方案见 [`PVZLUA_STUDIO_DESIGN.md`](PVZLUA_STUDIO_DESIGN.md)。

### 4.5 原生 DLL 插件中心

DLL 页面只管理和检查插件，不编辑二进制：

- 显示发布者、版本、SHA-256、签名状态、PE32/i386、入口导出、ABI、依赖和权限警告；
- 展示插件将注册的事件、Capability、Schema 和配置页面；
- 检查重复 Provider、Hook 声明冲突、缺依赖、循环和错误位数；
- 安装到 `pvzmod/plugins/native/<plugin-id>/` 的固定目录；
- 启用/禁用时显示依赖影响和“替换 DLL 必须完全退出游戏”的提示；
- 从不为了读取元数据而 `LoadLibrary` 第三方 DLL，静态 PE 检查和 manifest 验证放在隔离进程。

原生插件拥有游戏进程权限。管理器可以帮助显示风险、哈希和来源，不能把任意 DLL 宣称为安全沙箱内容。

### 4.6 资源中心

统一资源库管理图片、动画、音效、粒子和其他自定义资产：

- 缩略图、标签、类型、尺寸、编码、来源包、引用者和实际/估算内存；
- 按内容 ID、路径、哈希、未引用、重复、缺失或超预算搜索；
- 同哈希资源复用建议，但不在用户确认前自动改写引用；
- 图片尺寸/像素、动画 Transform、压缩/解压字节和总资源预算预警；
- 动画条目显示来源工程、交换包、路径和最近外部报告；实际编辑由用户在 `PvZAnimationStudio` 中完成；
- 扫描资源时不执行 Lua、DLL 或包安装脚本。

### 4.7 自定义内容中心

管理器提供统一目录与关系图，覆盖：

```text
Plant / Zombie / Projectile / Armor / Elite / Boss
Level / Wave / UI / Card / Resource / Behavior / Capability
```

每个内容页同时显示：

- 稳定 `ContentId`、包所有者和当前世代；
- 原版 Carrier、标签、资源、行为、配置和存档 Schema；
- 谁引用它、它引用谁、缺失项和冲突项；
- 运行时是否支持该能力，还是只有编辑器表单但尚无 Hook；
- 原始 JSONC 的精确文件与行号，以及 Lua 模块的受管路径、哈希和外部报告摘要；管理器不打开 Lua 代码。

动画制作器可以创建“基础植物草稿”，但只有导入管理器、分配包与 ContentId、通过运行时能力检查后，才成为可安装内容。

## 5. 用户界面

管理器采用大型工作台，而不是多个互不相通的小工具：

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 游戏档案 / 运行状态 / 当前包集合 / 验证 / 构建 / 应用 / 回滚       │
├───────────────┬─────────────────────────────────┬───────────────────┤
│ 工作区树       │ 多文档主编辑区                   │ 属性与引用检查器   │
│               │                                 │                   │
│ 总览           │ Dashboard / JSONC / Diff       │ Schema 表单        │
│ 包与依赖       │ Content / Resource / Graph     │ Owner / Generation│
│ 自定义内容     │ Plugin / Runtime / Publish     │ 依赖 / 冲突 / 预算 │
│ 资源           │                                 │                   │
│ Lua 资产       │                                 │                   │
│ 原生插件       │                                 │                   │
│ 配置与设置     │                                 │                   │
│ 冲突           │                                 │                   │
├───────────────┴─────────────────────────────────┴───────────────────┤
│ 问题 / 结构预检 / 运行日志 / 性能 / 文件变更 / 安装计划            │
└─────────────────────────────────────────────────────────────────────┘
```

关键页面：

- **总览**：版本健康、启用包、错误、预算、待重启和最近应用记录；
- **包与依赖**：依赖图、版本、所有者、启用状态和冲突；
- **自定义内容**：植物/僵尸/子弹/UI 等虚拟化目录及关系图；
- **资源**：图片、动画、音效、粒子和内存预算；
- **Lua 资产**：模块、所有者、版本、哈希、绑定、启用状态和外部报告摘要；不显示、验证或打开代码；
- **原生插件**：manifest、PE、ABI、hash、权限与重启；
- **配置**：Schema 表单、JSONC 源码、来源和覆盖层；
- **冲突**：同 ID、同 Provider、同字段、路径和依赖问题；
- **运行**：日志、世代、调用次数、耗时、命令队列和禁用原因；
- **发布**：干净构建、锁定文件、哈希、ZIP 和兼容性报告。

所有列表必须虚拟化；图片只加载可见缩略图；关系图和资源预览按需打开。所谓“超大型”是管理范围完整，不是把动画编辑器、Lua IDE 或全部资源正文塞进同一进程。

## 6. 源工作区与安装目录分离

多个包不能继续直接共同编辑一份 `textures.jsonc` 或 `custom_plants.jsonc`。管理器使用分包源工作区：

```text
<workspace>/author.package/
├─ package.jsonc
├─ content/
│  ├─ plants/
│  ├─ zombies/
│  ├─ projectiles/
│  └─ ui/
├─ config/
├─ scripts/
├─ assets/
│  ├─ images/
│  ├─ animations/
│  ├─ sounds/
│  └─ source/                 # 可选 .pvza 等作者源文件
├─ native/                    # 可选发布 DLL 和 manifest
└─ tests/
```

构建后投影到游戏目录：

```text
pvzmod/config/...
pvzmod/scripts/...
pvzmod/plugins/native/...
pvzmod/images/...
pvzmod/animations/...
pvzmod/sounds/...
```

源工作区是事实来源，游戏目录是可重建的安装结果。生成索引、缓存、缩略图数据库和搜索索引不覆盖作者文件，也不作为发布包唯一来源。

对于当前已经直接编辑 `pvzmod/` 的用户，首次导入时建立 `local.legacy` 包：管理器显示归属建议和差异，用户确认后再拆分，禁止未经确认搬动或删除现有文件。

## 7. 应用和回滚事务

每次“应用到游戏”固定经过：

```text
读取源工作区
  → 解析 JSONC/manifest，并按 manifest 盘点 Lua 文件与哈希
  → 解析依赖和 ContentId
  → 预检资源、包能力声明、ABI、预算和冲突（不验证 Lua 代码）
  → 生成下一世代与安装计划
  → 显示文件 Diff 和风险
  → 写入临时 staging 目录
  → 再次运行包结构/路径/资源/ABI headless 预检（不调用 Lua validator）
  → 原子替换可替换文件 / 记录需重启文件
  → 保存回滚清单和包锁定文件
```

任何一步失败都不修改已安装档案。JSON/Lua 热重载失败保留上一运行时世代；DLL、`pvzmod.dll` 或补丁器变化必须退出游戏后应用。卸载按所有者清单移除，不根据模糊文件名猜测。

## 8. 管理器内部架构

管理器界面可以很大，但内部禁止成为 God Object。建议拆分：

```text
modding/PvZModManager/
modding/PvZModManager.Core/
modding/PvZModManager.Tests/
modding/PvZMod.Contracts/          # 包、动画交换、诊断和运行协议
modding/PvZLuaStudio/              # 独立 Lua 编辑器
modding/PvZLuaStudio.Tests/
modding/tools/PvZPackageInspector/ # 包、路径、依赖和安装结构预检
modding/tools/PvZLuaValidator/     # 由 LuaStudio/CI 使用，不属于 Manager
modding/tools/PvZScriptLab/        # 由 LuaStudio 使用的隔离 Mock
```

核心服务：

- `WorkspaceService`：工作区、档案、最近项目和文件监视；
- `PackageGraphService`：依赖、版本、所有者、锁定和启用集；
- `LosslessJsoncService`：保注释 AST、Schema 表单和最小差异；
- `ContentCatalogService`：所有内容类型、引用和稳定 Handle；
- `ScriptAssetRegistry`：只管理 Lua 文件、模块元数据、哈希、绑定关系和外部报告摘要；
- `NativePluginInspector`：manifest、PE、hash、ABI 和信任信息；
- `ResourceIndexService`：元数据、缩略图、哈希、引用和预算；
- `InstallPlanner`：staging、Diff、应用、回滚和档案锁定；
- `RuntimeBridge`：可选命名管道、日志、诊断和安全点重载；
- `PublishService`：干净构建、测试、ZIP 和兼容报告。

三个桌面工具只共同引用轻量 `PvZMod.Contracts`。管理器不引用 AnimationStudio/LuaStudio 的 WPF ViewModel、编解码器、语言服务或编辑控件；两个 Studio 也不引用管理器的安装器和包管理 UI。

## 9. 与运行时的连接

管理器默认可以完全离线工作。实时功能使用版本化命名管道，而不是让 64 位 WPF 工具直接读取 32 位游戏内存：

- 查询运行时版本、当前包世代、事件/Capability 和最近错误；
- 请求 JSON/Lua 安全点重载；
- 订阅有限速的结构化日志和性能计数；
- 禁用某个 owner 的新回调；
- 获取只读实体摘要用于调试，不返回裸指针。

运行时未连接时，包/配置管理、安装计划和资源索引仍可使用；Lua 验证与 Mock 由独立 `PvZLuaStudio` 离线完成。连接协议不允许任意地址读写、调用函数或安装 Hook。

## 10. 安全和数据保护

- 扫描包不执行 Lua、DLL、安装脚本或任意外部命令；
- DLL 元数据在隔离检查进程中读取，管理器进程不 `LoadLibrary`；
- ZIP、图片、动画和路径执行文件数、大小、解压量、像素和 reparse-point 限制；
- 应用前展示完整 Diff，默认不覆盖未知所有者文件；
- 自动保存恢复日志，崩溃后能继续或放弃未提交事务；
- 每次应用产生可恢复快照，但大资源使用内容寻址复用，避免无限复制；
- 凭据、私钥和本地游戏路径不写入可发布包；
- 原生插件始终显示可信代码警告，不能用绿色“安全”徽章淡化风险。

## 11. 学习曲线重新归属

“1 小时上手、10 小时熟悉、30 小时近乎掌握”仍然保留，但工具责任改为：

- 动画制作学习由 `PvZAnimationStudio` 自己的教程负责；
- Lua 学习由 `PvZLuaStudio` 的编辑器、向导、Mock、Cookbook 和诊断负责；
- 包、配置、资源和安装学习由 `PvZModManager` 负责；
- 原生 DLL 不纳入 30 小时 Lua 目标，单独提供可信插件 SDK 和 ABI 教程。

新的 60 分钟 Lua 流程在 `PvZLuaStudio` 中完成：

| 时间 | LuaStudio 操作 | 结果 |
| --- | --- | --- |
| 0–10 分钟 | 选择游戏档案并运行内置示例 | 版本、运行时和日志健康 |
| 10–20 分钟 | 修改示例 Lua 参数 | Mock 和游戏安全点重载反馈 |
| 20–35 分钟 | 在 LuaStudio 中“新建行为” | 创建 Lua、写绑定、验证并打开待编辑行 |
| 35–50 分钟 | 添加条件/计时并观察命令 | 事件、状态和命令可视化 |
| 50–60 分钟 | 制造错误、修复、生成脚本模块产物 | 中文诊断、源码哈希和校验报告通过；安装另由 Manager 完成 |

## 12. 分阶段实施

### M0：共享契约和 Headless Core

- 先定义包、ContentId、动画交换、诊断和安装计划 Schema；
- 建立 `PvZPackageInspector`、测试夹具和 lossless JSONC 原型；
- 让运行时测试与管理器测试共享合法/非法配置样本。

验收：命令行能读取当前 `pvzmod`，输出内容清单、来源、错误和不会执行的安装计划。

### M1：工作区、档案、配置和资源

- 完成游戏档案、包工作区、配置双视图、资源索引、Diff、staging 和回滚；
- 导入现有目录为 `local.legacy`；
- 支持导入动画制作器的资产交换包并创建基础植物草稿。

验收：不接入 Lua/DLL 也能安全管理当前全部 JSON/JSONC、图片和动画，应用失败不改变游戏目录。

### M2：Lua 资产管理接入

- 读取 Lua 模块 manifest、哈希、绑定关系和 `PvZLuaStudio`/CI 外部报告摘要；
- 完成模块启用、禁用、安装、卸载和 ExtensionHub 世代管理，但不加入代码编辑或语言验证。

验收：管理器能管理 Lua 资产却无法显示、编辑、验证或打开代码；首次使用者的 60 分钟原创技能目标由独立 `PvZLuaStudio` 验收。

### M3：原生插件中心

- 完成 manifest/PE32/hash/ABI/依赖检查、可信警告和固定目录安装；
- 显示 Capability/Event 注册预览和重启要求。

验收：管理器在不加载 DLL 的情况下拒绝错误位数、错误 ABI、缺依赖、重复 Provider 和路径逃逸。

### M4：实时诊断和规模化

- 完成运行时连接、世代、结构化日志、性能计数、owner 禁用和安全点重载；
- 对 100 包、10000 内容、5000 资源和大型日志使用虚拟化/增量索引压力测试。

验收：管理器启动和常用搜索不加载全部资源正文；一个包刷日志或验证失败不阻塞其他包编辑。

### M5：发布和生态

- 完成锁定文件、干净目录安装测试、发布 ZIP、兼容报告、升级/降级和迁移预览；
- 动画制作器现有“直接合并配置”降为兼容入口，默认改为导出资产包并交给管理器。

验收：发布包可从空档案重建；源工作区、安装投影和回滚记录一致；AnimationStudio 不再承担 Mod 总管理。

## 13. 总体验收标准

- `PvZAnimationStudio` 中不存在 Lua 编辑器、DLL 管理器、包依赖图或全局配置中心；
- `PvZLuaStudio` 可以在一次事务中创建 Lua、写绑定、验证并打开待编辑位置；
- `PvZModManager` 只管理 Lua 模块、所有者、版本、哈希、绑定关系、启用状态和外部报告摘要，不显示、验证或打开代码；
- 当前及未来所有业务 JSON/JSONC 都能显示来源、Schema、原始文本、表单和安装 Diff；
- DLL 扫描不加载二进制，替换时要求游戏完全退出；
- 图片、动画、音效和其他资源拥有所有者、引用、哈希和内存预算；
- 植物、僵尸、子弹、UI 等内容使用统一 ContentId 和关系图；
- 一个坏包不会破坏其他包或已安装的上一有效档案；
- 管理器数据库/缓存删除后能从普通源文件重建；
- 手工编辑文件仍完整可用，管理器不会锁定用户到私有格式；
- 所有应用操作可预览、可验证、可追踪、可回滚；
- 工具明确区分“编辑器能描述”与“当前运行时已经支持”，禁止表单先于 Hook 就宣称功能可用。

## 14. 最终边界

`PvZAnimationStudio` 应当成为优秀而专注的动画工具，`PvZLuaStudio` 应当成为专注的行为代码工具，`PvZModManager` 则是整个 Mod 生态的管理工作台。三者读取同一源工作区和公开契约，但管理器不负责启动或打开 Lua 代码，任何一方也不能吞并另外两方。

这样动画作者专注动画，Lua 作者专注行为代码，包维护者专注配置、依赖、插件、资源和安装。超大型管理器承担的是**统一管理、归属、安装和回滚**，不承担动画制作、Lua 验证/打开代码、运行时 Hook 或二进制执行。
